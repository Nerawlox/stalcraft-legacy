# Запуск на двух компьютерах Windows

Инструкция относится к двум отдельным самодостаточным комплектам: серверному и клиентскому. В каждом архиве находится совместимый runtime Java 8; устанавливать Python или менять системную Java не нужно. Комплекты содержат игровые бинарные файлы и не публикуются в Git или вместе с исходниками проекта. Передавайте другу клиентский ZIP напрямую и храните оба комплекта локально.

## Подготовка сети

Для компьютеров в одной домашней сети серверу и клиенту обычно достаточно IPv4 адреса сервера из локальной сети. Если компьютеры находятся в разных сетях, установите Radmin VPN на оба компьютера и подключите их к одной частной VPN-сети по инструкции [Radmin VPN](https://www.radmin-vpn.com/help/). Не используйте публичный адрес или адрес шлюза: нужен IPv4, назначенный самому компьютеру-серверу.

Распакуйте оба ZIP в постоянные папки на соответствующих компьютерах. На серверном компьютере запустите серверный комплект и в появившемся окне выберите назначенный ему адрес: частный адрес локальной сети или адрес интерфейса Radmin VPN. Запомните выбранный адрес и оставьте стандартный порт `25576`. Этот же адрес понадобится клиенту, даже если клиентская игра запущена на компьютере-сервере.

## Запуск сервера

1. Откройте `Verify-Files.cmd`, чтобы сверить файлы комплекта. Если проверка сообщает об ошибке, не продолжайте запуск.
2. Запустите `Start-Server.cmd`, выберите локальный IPv4 адрес сервера и дождитесь сообщения `Сервер готов` после строки `Done`.
3. На компьютере-сервере запустите `Allow-Connection.cmd` от имени администратора. Введите IPv4 адрес клиента в той же сети: адрес его интерфейса Radmin VPN при соединении через Radmin или LAN IPv4 при соединении по локальной сети. Убедитесь, что сервер уже запущен и его адрес сохранён в настройках комплекта.

Помощник Windows создаёт узкое входящее правило для Java из серверного комплекта, выбранного адреса сервера, введённого адреса клиента и порта `25576`. Подтвердите запрос Windows. Не создавайте вместо этого правило для всех программ, адресов или портов. Текущая инструкция рассчитана на одного разрешённого клиента; одновременное подключение нескольких внешних клиентов ещё не заявлено.

Чтобы отменить доступ, запустите `Remove-Connection.cmd` от имени администратора. При смене сети или адреса повторите настройку сервера и правила для нового адреса.

## Подключение клиента

1. На компьютере клиента откройте `Verify-Files.cmd`.
2. Запустите `Check-Connection.cmd` и введите выбранный адрес сервера. Если параметр не передать, комплект спросит адрес. Проверка сообщает только, доступно ли TCP-соединение к адресу и порту; это не проверка входа в Minecraft.
3. Если TCP-проверка прошла, откройте `Start-Client.cmd`. Введите тот же адрес сервера, порт `25576` и уникальное имя игрока из 1–16 символов ASCII: латинские буквы, цифры или `_`. Не используйте одинаковые имена для двух игроков.

Сначала подключите клиента к серверу и проверьте вход в мир и чат. Если соединение не устанавливается, сверьте адреса и порт, убедитесь, что сервер всё ещё показывает `Done`, и проверьте, что `Allow-Connection.cmd` разрешил именно клиентский адрес. Для диагностики повторно используйте `Check-Connection.cmd`.

## Остановка и сохранения

Закройте клиент обычным способом. На сервере запустите `Stop-Server.cmd` и дождитесь сообщения о завершении процесса. Сервер сохранит мир при штатной остановке. Для резервной копии сначала остановите сервер и дождитесь его выхода, затем скопируйте папку `game` из серверного комплекта в отдельное место. Не копируйте её во время работающего сервера.

## Границы проверки

Локальный сервер и два клиента проверялись на одном компьютере через `127.0.0.1:25576`. Подключение с двух физических компьютеров, включая работу через Radmin VPN, ещё не проверено. TCP-проверка подтверждает только доступность порта. Полноценная боевая система, урон и NPC не подтверждены; см. [отчёт о проверке](validation.md).
